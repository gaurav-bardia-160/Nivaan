============================================================
1. SHORT SUMMARY
============================================================

GovBank Assistant is planned as an AI-powered communication assistant that helps ordinary users understand government, legal, and banking information in simple language.

The main problem:
Official forms, schemes, legal notices, tax procedures, and banking documents often use complex language. People misunderstand them, miss deadlines, lose benefits, or depend on agents because the communication between institutions and citizens is unclear.

The planned solution:
A web app where a user can ask a question, and later upload a fictional or safe document, then receive:

- a plain-language summary
- documents needed
- step-by-step procedure
- warnings about deadlines, penalties, or risky clauses
- source URL and last verified date
- privacy notice and disclaimer
- future translation and voice output

Important framing:
This is not a legal advisor, tax advisor, financial advisor, or autonomous decision maker. It is an explanation and guidance assistant. It should help users understand and prepare, not tell them final decisions like "sign this", "ignore this notice", or "take this loan".

============================================================
2. EVENT THEME CONNECTION: COMMUNICATION
============================================================

The event theme is communication. This project connects directly because it solves a communication gap between official institutions and normal citizens.

The project translates communication across several barriers:

1. Formal to simple
   Official language becomes plain language.

2. Written to guided action
   A form or notice becomes a checklist.

3. English to regional language
   Future support can include Hindi and Gujarati.

4. Static document to conversation
   The user can ask follow-up questions.

5. Institution to citizen
   Government, legal, and banking instructions become understandable.

One-line pitch:
GovBank Assistant bridges the communication gap between institutions and citizens by turning complex official language into clear, sourced, step-by-step guidance.

6. HIGH-LEVEL SYSTEM DESIGN
============================================================

There are two main phases.

Phase 1: Offline knowledge building
This happens before users use the app.

Phase 2: Online user serving
This happens each time a user uses the website.

------------------------------------------------------------
6.1 Phase 1: Offline knowledge building
------------------------------------------------------------

Goal:
Create a small trusted knowledge base from official sources, then later build an index for semantic search.

Planned flow:

1. Choose sources
   File: backend/data/sources.json
   The team lists official source URLs grouped by area:
   - tax
   - banking
   - schemes
   - legal

2. Crawl sources
   File: backend/offline/crawl.py
   Later this will download approved official pages or PDFs and save raw text into backend/data/raw/.

3. Clean and chunk text
   File: backend/offline/clean_chunk.py
   Later this will remove page clutter, menus, repeated headers, and split text into chunks of about 300 to 500 words.

4. Structure entries
   File: backend/offline/structure.py
   Later this may use AI to turn cleaned chunks into structured entries like:
   - title
   - category
   - documents needed
   - steps
   - fees
   - common mistakes
   - source URL
   - last checked date
   - status: unverified

5. Verify manually
   File: backend/offline/verify.py
   A human must check important entries before they become trusted.
   High-stakes entries must not go live without review.

6. Store verified knowledge
   File: backend/data/knowledge_base.json
   This should contain verified entries only.

7. Build vector index
   File: backend/offline/build_index.py
   Later this will create embeddings and save a searchable index into backend/data/vector_index/.

Important first-version simplification:
Do not build crawler, embeddings, or full vector database immediately. Start with 3 manual entries in knowledge_base.json. Suggested first entries:

- PAN card application guide
- ITR filing basics guide
- loan agreement explainer guide

------------------------------------------------------------
6.2 Phase 2: Online user serving
------------------------------------------------------------

Goal:
Take a user question or future document, safely process it, retrieve verified context, and return a structured answer.

Planned full flow:

1. Website input
   Files: frontend/index.html, frontend/style.css, frontend/app.js
   User types a question, chooses language, and later may upload a fake or safe document.

2. FastAPI endpoint
   File: backend/main.py
   Later this exposes POST /api/ask.

3. Pipeline orchestration
   File: backend/pipeline.py
   This calls the modules in order.

4. OCR or typed input handling
   File: backend/modules/ocr.py
   Typed text passes through. Future image or PDF uploads are converted to text.

5. Privacy masking
   File: backend/modules/privacy.py
   Planned to mask Aadhaar, PAN, phone, email, and bank account numbers before external AI use.

Important privacy correction:
If the backend receives the document, the backend sees the original document first. So the correct claim is "masked before external AI", not "nobody sees it". True on-device masking would be a later separate feature.

6. Routing
   File: backend/modules/router.py
   Decides:
   - question or document
   - banking, tax, scheme, legal, or unknown
   - whether a clarification is needed

7. Retrieval
   File: backend/modules/retrieval.py
   Finds the best matching verified knowledge entry or chunks.
   Early version can use keyword search.
   Later version can use embeddings and vector search.

8. Flagging
   File: backend/modules/flagger.py
   Scans document text for deadlines and risky clauses.
   Examples:
   - penalty charges
   - high late fee
   - prepayment clause
   - auto-renewal clause
   - respond within 15 days

9. Explanation
   File: backend/modules/explainer.py
   AI or deterministic logic creates a fixed-shape answer using only retrieved material.
   It must not invent steps, fees, or laws.

10. Tool checks
   File: backend/modules/tools.py
   Later this can check official pages for current fees, deadlines, or circulars.
   Only trusted official domains should be used.

11. Agent loop
   File: backend/modules/agent.py
   Later this decides whether to:
   - ask a clarification question
   - retrieve more chunks
   - call a tool
   - continue the conversation
   - abstain when data is missing

Do not build agent.py first. Build the basic direct pipeline first.

12. Translation and voice
   File: backend/modules/translate_voice.py
   Later it converts the answer to Hindi or Gujarati and can generate audio.

13. Frontend display
   Files: frontend/index.html, frontend/style.css, frontend/app.js
   Shows:
   - summary
   - documents needed
   - steps as tick boxes
   - warning box
   - masked items panel
   - source URL
   - last verified date
   - disclaimer

10. PRIVACY AND SAFETY RULES
============================================================

This project handles high-risk categories:

- government IDs
- tax information
- legal notices
- bank accounts
- income information
- personal addresses

Important rules:

1. Do not use real user documents during development.
2. Use only fake documents in samples/fake_documents/.
3. Never commit .env files.
4. Never commit API keys.
5. Never commit real documents.
6. Do not claim perfect privacy.
7. Do not claim the tool gives legal, tax, or financial advice.
8. Do not let the AI make final decisions for users.
9. Show sources and dates on every answer.
10. If the source is missing, abstain instead of guessing.

Correct privacy wording:
The system should mask sensitive values before sending text to an external AI provider.

Incorrect privacy wording:
Nobody sees your document.

Why incorrect:
If the backend receives the file, the backend sees the original file before masking.

Future improvement:
True on-device masking in the browser could reduce backend exposure, but that is a separate advanced feature.

============================================================
11. AI BEHAVIOR RULES
============================================================

The explainer or agent must follow these rules:

1. Answer only from retrieved verified context.
2. Do not invent fees, dates, laws, deadlines, or steps.
3. Copy source_url and last_verified from code or data, not from model-generated text.
4. If the knowledge base does not cover the request, say so.
5. For high-stakes legal, tax, or financial matters, explain and flag, then advise checking with a professional or official source.
6. Use neutral language like "worth checking" instead of "bad" or "illegal".
7. Never say "you should sign", "you should ignore", or "you are guaranteed".
8. Provide reasons for warnings.
9. Keep final decision with the user.

12. WHAT MAKES THIS DIFFERENT FROM A GENERIC CHATBOT
============================================================

A generic chatbot:

- answers from model memory
- may hallucinate
- may not show sources
- may not follow a workflow
- may not protect privacy
- may not say when it does not know

GovBank Assistant should:

- retrieve from verified knowledge
- show sources and dates
- return structured checklist answers
- mask sensitive values before external AI calls
- flag deadlines and risky clauses
- ask clarifying questions later through agent.py
- abstain when no verified data exists
