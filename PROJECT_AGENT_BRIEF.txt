GovBank Assistant agent brief
Updated: 2026-10-04

Purpose
GovBank Assistant helps users understand government, banking, tax, and legal procedures/documents in plain language. It is a communication-gap project: official language is hard for citizens to understand, so the assistant explains, flags risks, shows sources, and refuses to guess outside the knowledge base.

Current status
- Runnable partial project, not a skeleton.
- Backend API works for typed questions and file uploads.
- Frontend chat UI is connected to backend.
- Tests currently pass: 44 passed.
- Project is still not production-ready because data is small/unverified, scanned OCR is missing, and translation/voice is not real yet.

Main working endpoints
- GET /api/health
- POST /api/ask
- POST /api/ask-file

Main current workflow
1. User types a question or uploads a `.txt` / text-based PDF.
2. Backend extracts text without storing the upload.
3. Guardrails mask common sensitive values such as PAN, Aadhaar, phone, email, IFSC, and account number patterns.
4. Agent routes the request and decides if a known guide/category matches.
5. Retrieval finds the closest local knowledge entry.
6. Explainer creates a structured answer from local data only.
7. Guardrails add neutral warnings for deadlines, penalties, prepayment/foreclosure, auto-renewal, extra fees, and legal notices.
8. Frontend renders summary, steps, warnings, source, date, disclaimer, and masked items.

Important module guidance
- New privacy/risk work should go into backend/modules/guardrails.py.
- New routing/agent decision work should go into backend/modules/agent.py.
- New offline ingestion work should go into backend/offline/data_builder.py.
- Keep compatibility wrappers unless there is a clear reason to remove them.
- Do not add LLM calls until prompts, privacy rules, and provider config are agreed.

Answer shape
Every backend answer should preserve this contract:
- title
- summary
- documents_needed
- steps
- warnings
- source_url
- last_verified
- confidence
- masked_items
- disclaimer

Privacy rules
- Do not store uploaded files.
- Mask before retrieval/explanation.
- Do not claim client-side privacy yet because masking is backend-side.
- Use fake documents for demos and tests.
- Do not send real confidential user data in tests.

Safety rules
- Explain and flag, do not decide for the user.
- Do not say “take this loan”, “ignore this notice”, or “sign this agreement”.
- For high-stakes legal/tax/financial cases, recommend checking an official source or qualified professional.
- If no guide matches, refuse to guess.

Current limitations
- Knowledge base has only three starter entries and they are still unverified.
- Scanned PDF/image OCR is not implemented.
- Backend answer translation and voice are not implemented.
- Official live-source updater is not implemented.
- Client-side masking is not implemented.
- Deployment hardening and observability are not complete.

Recommended next build order
1. Expand and manually verify knowledge_base.json.
2. Add realistic fake demo documents and tests.
3. Add client-side masking or keep privacy copy conservative.
4. Add backend translation no-op and explicit unsupported-language handling.
5. Add scanned OCR only after privacy and accuracy tests are ready.
6. Add official-source update checker with human approval.
7. Add production hardening and CI.

Good demo paths right now
- Typed: “How do I apply for a PAN card?”
- Typed: “What should I check in a loan agreement?”
- Upload fake `.txt` with PAN, late fee, and 15-day deadline.
- Upload fake text-based PDF with PAN, late fee, and 15-day deadline.

Avoid claiming
- Official verified accuracy.
- Full legal/tax/financial advice.
- Scanned image OCR.
- Client-side/on-device privacy.
- Real multilingual answer translation.
